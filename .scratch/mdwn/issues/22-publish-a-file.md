# 22: Publish a File: Publication, Public representation, and Public reader

**What to build:** An Owner publishes one File to a public link that anonymous readers can decrypt and read, keeps it live as they edit, and can hand out that link knowing the read capability never reaches the service; a Collaborator can instead ask the Owner to publish.

**Blocked by:** 15 (Editor and preview workspace), 17 (Shares and Grants).

**Status:** ready-for-agent

- [x] A Publication exposes exactly one File, is independent of Shares, follows File identity through rename and move, and presents the latest successfully saved representation; a partial unique constraint allows at most one active-or-deleting Publication per File.
- [x] Only the File Owner may create, configure, or later rotate or unpublish a Publication. An active Collaborator with File access may create one pending Publication request that the Owner approves or denies and the requester may cancel; denial or cancellation removes the pending request, and a request never creates public access on its own.
- [x] Creation generates a never-reused, independently generated 256-bit random base64url Publication path identifier that is sent to the service, and a versioned read-only decryption capability that stays in the URL fragment and is never sent to the service.
- [x] The service stores a public encryption key so an authorized File editor can update the encrypted Public representation without learning the fragment capability or gaining Publication-management authority.
- [x] The Public route contains only the opaque Publication identifier; the read capability is entirely after `#`; possession of a complete active URL is sufficient to read the current Public representation, and downloaded material cannot be recalled.
- [x] The Public page renders sanitized GFM and, if present, the File title; it shows no raw front matter, path, breadcrumbs, user-authored timestamps, or Owner identity; it sends `noindex`, `nofollow`, and `noarchive`; it is non-indexed by default and uses no analytics, third-party scripts, or nonessential cookies.
- [x] The Owner may opt into selected pseudonymous author attribution; attribution is off by default and never inferred from edit activity.
- [x] The Public representation is one decoded encrypted presentation payload of at most 524,288 bytes, separate from the private representation and stored with the same enforced bound.
- [x] After publication, any authorized File editor's save creates both the private and Public representations under one File-revision condition using the stored public key rather than the fragment; the Public pointer updates in the same operation as the private one.
- [x] An unknown path identifier returns a ciphertext-free `404` indistinguishable from the response for a rotated or sealed link.
- [x] Tests prove the paired save is atomic, the fragment never appears in requests, logs, errors, analytics, referrers, or server state, anonymous routes never return private or Collaborators-only ciphertext or envelopes, and a pending request creates no public access.
