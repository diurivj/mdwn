# 33: MVP acceptance suite and security-review readiness

**What to build:** A release candidate that has been proven against the specification's acceptance criteria on real browsers and a disposable remote Workers Free + D1 deployment, with the independent security review scheduled before any end-to-end-security claim.

**Blocked by:** 01–32 (every ticket above).

**Status:** ready-for-agent

**Related follow-ups:** [37: TypeScript runtime project boundaries](37-typescript-runtime-project-boundaries.md); [38: D1 export-based database restoration](38-d1-export-database-restoration.md).

- [ ] Privacy and cryptography: integration tests prove no private name, Markdown, front matter, Comment body, or displayed pseudonym reaches Worker or D1 plaintext; passkeys cannot derive or decrypt content; envelope contexts reject cross-purpose, cross-object, stale-epoch, malformed, and downgrade attempts; nonce uniqueness survives concurrent tabs, devices, retries, and interrupted jobs; public fragments never appear in requests, logs, errors, analytics, referrers, or server state; anonymous routes never return private or Collaborators-only ciphertext or envelopes.
- [ ] Cross-browser (Chromium, Firefox, WebKit): vectors cover encryption/decryption, device approval, sharing, rotation, and Publication reading; the full normal-authentication-plus-phrase recovery path works without exposing the phrase or plaintext keys to requests, service state, logs, or telemetry; recovery-code-only access cannot read content before replacement-Passkey enrollment, a fresh assertion, and Vault recovery; a browser authenticated by a synced passkey cannot read private content before QR-approved routine enrollment; multiple enrolled devices and their device-bound Sessions coexist with owned and provisioned Grant authority; eviction, private-mode loss, and a missing device route to recovery or enrollment rather than an unrecoverable error.
- [ ] Authentication and abuse: signup requires valid one-use fixed-difficulty proof of work and WebAuthn and replay fails; all exact rate-limit windows and scopes and generic failures are tested; recovery-code consumption, set replacement, restricted recovery Session, global Session revocation, and no-override failure are tested; the signup bootstrap transaction invariants hold with no failure mode leaving an Account without its capsule or root-capability envelope; the phrase gate blocks content creation until verification; a lost commit response rebinds by sign-in plus Device proof; raw IP and prohibited request/content fields never persist; the scheduled retention purge is exercised.
- [ ] Hierarchy, sharing, and concurrency: same-owner containment, root uniqueness, cycle prevention, node kind, and entry/node agreement are enforced; the required Unicode fixtures assert display and comparison-key bytes in Chromium, Firefox, WebKit, and the Worker test target; unsafe segment and path boundaries are rejected; deterministic suffix placement, literal suffixes, folded collisions, source-duplicate rejection, direct-name reservation, and generated over-limit names are covered; a same-revision two-client mutation commits exactly once with a `409` loser and no visible partial Import; direct File Grants reveal no tree or path data; the complete permission matrix is covered; overlapping Grant union and revocation behave independently; revocation denies server access before rotation and blocks new writes until safe; stale saves preserve the local draft and mutate nothing.
- [ ] Publications and Comments: unknown, rotated, and sealed Publication paths return indistinguishable ciphertext-free `404` responses; public pages expose only the current Public representation and allowed public epochs; audience transitions never disclose Collaborators-only history publicly; a signed-in but unauthorized Account receives no Collaborators-only data; Owner and author Comment mutation rules are enforced server-side; link rotation preserves the logical Public thread while unpublish destroys it and a later Publication starts fresh; interrupted teardown remains sealed and Owner-resumable; pseudonym update shows all-old or all-new state and never mixed committed attribution.
- [ ] Import, export, and deletion: export plaintext is produced only in the browser and includes only owned content plus defined historical Private Comment data; every local import bound and preflight failure creates no session, upload, or visible row; the remote Workers Free + D1 proof covers exact-boundary acceptance and one-unit-over rejection for the staging manifest, chunk, aggregate, chunk count, records per chunk, every canonical ciphertext cap, and Historical Comment count; the same proof shows worst-case upload and commit fit the 50-statement D1 Free invocation limit, exact duplicate retries are idempotent, and mismatched retries, missing sequences, malformed descriptors, cancellation, expiry, disconnect, stale authority, and failed commit create no marker or visible data; a staged Replace retains the old representation until a successful marker; shared-target imports assign every new descendant to the target Owner; uncommitted Import records are excluded from every normal query class; File and ≤500-node Directory hard deletion remove every dependent application record atomically, >500-node deletion changes nothing, and Public-participation limits cannot block export, hard deletion, unpublish, or session revocation.
- [ ] Delivery quality: type checking, unit tests, integration tests, migration validation, and a production build pass in pull requests; foreign-key checks are enabled with reviewed `EXPLAIN QUERY PLAN` output; migration rollback is rehearsed on non-production data; accessibility-sensitive controls are keyboard- and screen-reader-usable; a disposable remote Workers Free + D1 deployment is run as a release gate for release candidates and whenever encryption-persistence schema changes; and an independent security review is arranged before any end-to-end-security claim is made.
