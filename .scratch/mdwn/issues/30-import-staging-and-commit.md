# 30: Import staging, Import commit marker, and Historical Comments

**What to build:** A confirmed import uploads only encrypted, digest-checked staging data and then becomes visible all at once — so a person either sees the whole imported tree or sees nothing, and an interrupted or retried upload leaves no half-imported Files.

**Blocked by:** 29 (Import preflight and review).

**Status:** ready-for-agent

- [ ] Confirmation creates an unguessable, initiating-Account-bound Import session with a 24-hour expiry and the browser's encrypted staging manifest of at most 131,072 bytes, with its SHA-256 digest, expected record and chunk counts, and aggregate digests; the manifest binds the reviewed plan and contains no raw Archive manifest, Markdown, sidecar, plaintext name, or capability.
- [ ] The browser uploads 1–40 raw binary encrypted chunks of at most 524,288 bytes each, each with a 32-byte SHA-256 digest and 1–50 complete typed canonical-record descriptors; `(import_id, sequence)` is unique with 0-based sequence below 40; a session accepts at most 20,971,520 bytes of chunk payload and 2,000 descriptors in aggregate.
- [ ] A descriptor contains only record kind, opaque fixed-size IDs/references, offset, length, and digest, and each canonical encrypted payload occupies exactly one descriptor range; there is no free-form descriptor, metadata, retry, JSON, or base64 field that can carry additional content.
- [ ] The Worker rejects an excessive declared length and streams and counts the raw body before buffering it; without decrypting private content it validates binary envelope/header, descriptor kind/range/count, opaque references, digest, per-field limit, session state, and authorization, and persists no plaintext path, name, Markdown, Comment, capability, raw Archive manifest, raw ZIP, sidecar, free-form metadata, or alternate base64/JSON payload.
- [ ] Every canonical encrypted Import field respects its decided ceiling, enforced by browser validation, Worker validation, and D1 `CHECK` constraints: File representation 524,288 bytes; Directory-entry display-name/order ciphertext 4,096 bytes; Key envelope ciphertext 16,384 bytes; Historical Comment body ciphertext 16,384 bytes; Historical Comment attribution/displayed-pseudonym ciphertext 4,096 bytes; any other Import-created auxiliary encrypted record 16,384 bytes. The Worker, not the client, conditionally maintains aggregate counts and bytes.
- [ ] The only retry identity is `(import_id, sequence, SHA-256(payload))`: the exact same bytes return the original success without duplicate records, while a different body or digest for an accepted sequence permanently fails that session and requires a new preflight and session.
- [ ] Before commit the Worker rechecks initiator, target Owner, current target authority, expiry, every expected sequence/digest/count exactly once, structural and key constraints, collision actions, canonical field bounds, and reviewed revisions; a stale target, Grant, Owner, or revision returns to review and creates no commit marker.
- [ ] The final small transaction writes the immutable commit marker; every normal tree, File, direct-read, Share, export, count, and background query requires either a non-Import record or a matching commit marker, so the complete hierarchy and any authorized Replace become visible together. A staged Replace leaves the old representation current until that marker exists.
- [ ] Cancelled, expired, disconnected, mismatched, or failed sessions create no visible content and are cleaned up; every canonical staged record carries the immutable Import ID.
- [ ] Historical Comments from the local sidecar (at most 1,000; the 1,001st, malformed, or oversized record rejects the entire Import without omission) start a fresh Private thread as historical display data and reinstate neither former capabilities nor author mutation authority.
- [ ] A disposable remote Workers Free + D1 proof validates exact and one-unit-over limits, retries and mismatches, expiry, failure, and stale-authority cases, no-visible-partial-tree behavior, and that every permitted worst-case upload and commit fits the 50-statement D1 Free invocation limit. If the proof fails, the bounded plan is reduced or made more efficient — never silently require a paid plan.

## Comments

- 2026-09-21: Dependency note from ticket 03: staged envelopes use `app/crypto/enc-v1` (`docs/enc-v1.md`) with purposes `import-staging-manifest`, `import-chunk`, and `archive-manifest`. The Worker uses `inspectEnvelope` for structural, unauthenticated header validation only — the header becomes authenticated only after a successful open. `digestEnvelope` gives the whole-envelope SHA-256 identity. On an exact `(import_id, sequence, SHA-256(payload))` retry the browser must reuse the stored bytes verbatim and must never re-encrypt. The per-purpose caps in this ticket (16 KiB Key envelope, and so on) are tighter than the library backstop of 512 KiB.
